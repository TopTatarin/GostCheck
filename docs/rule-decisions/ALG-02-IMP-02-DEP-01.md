# Решение по ALG-02, IMP-02 и DEP-01: только ручная проверка

- **Дата фиксации решения:** 2026-07-30
- **Статус:** утверждено
- **Источник письменного утверждения:** текст задания `docs(rules): mark remaining
  rules as manual only` и PR
  <https://github.com/TopTatarin/GostCheck/pull/47>
- **Затронутые правила:** `ALG-02`, `IMP-02`, `DEP-01` из `rubric.yaml`
- **Область действия:** все профили работы, в которых соответствующее правило
  применимо

## Решение

- `ALG-02`: manual_required
- `IMP-02`: manual_required
- `DEP-01`: manual_required

Все три правила проверяются только человеком. GostCheck не выполняет по ним
formal, semantic, vision, OCR или эвристическую проверку. Автоматизация этих
правил в рамках текущего продукта не реализуется. Интерфейс ручной проверки,
чек-лист, ввод решения пользователя и workflow подтверждения также не
реализуются.

Правила остаются в `rubric.yaml` и в матрице покрытия
[docs/rule-coverage.md](../rule-coverage.md); они не скрываются и не переводятся
в `excluded_scope`.

## Что означает статус manual_required

- `manual_required` — это метаданные покрытия, а не результат проверки
  конкретного документа.
- `manual_required` не означает PASS, FAIL, WARN или UNVERIFIABLE.
- Отсутствие автоматического finding по этим правилам **не является PASS** и не
  означает успешное прохождение проверки.
- Эти правила не влияют на formal gate, на `severity_final` и на exit code
  запуска.
- Эти правила не создают semantic или vision findings.
- `manual_required` не считается implemented и не увеличивает число semantic
  implemented; в список semantic not_implemented эти правила не попадают, так как
  этот список описывает только semantic RuleSpec.
- Наличие правил со статусом `manual_required` не является ошибкой запуска и не
  делает report неполным.

## Кто выполняет проверку

Проверку выполняет нормоконтролёр вне GostCheck. Продукт не собирает, не
передаёт и не сохраняет результат этой ручной проверки: в `report.json` нет и не
появляется поля для её фиксации.

Персональные данные проверяющего (ФИО, подпись, служебный идентификатор) в
решении не фиксируются: они не были предоставлены и не выдумываются. Решение
утверждено в тексте задания, ссылка на PR приведена выше.

## Основание решения

### ALG-02 — «В блоках схемы минимум текста»

Проверка достаточности текста внутри блок-схем требует визуальной и
содержательной оценки человеком. GostCheck не анализирует текст внутри блок-схем
и не пытается определять, достаточно ли его для понимания алгоритма.

### IMP-02 — «Скриншоты исходного кода не рекомендуются»

Классификация изображений как скриншотов исходного кода, IDE, терминала, логов,
графиков, интерфейсов или смешанного содержимого требует визуального и
контекстного решения человека. GostCheck такую классификацию не выполняет.

### DEP-01 — «Отсутствие первого лица»

Норма об использовании первого лица и исключениях для цитат, авторских
формулировок и контекстно допустимых конструкций требует редакционного решения
нормоконтролёра. GostCheck не ищет местоимения, глагольные формы или иные
признаки первого лица для этого правила.

## Вне текущего scope

- автоматизация ALG-02, IMP-02 и DEP-01 любым слоем проверки;
- vision advisory по этим правилам;
- ручной workflow: UI, чек-лист, ввод и подтверждение решения человеком,
  хранение его результата.

Пересмотр решения возможен только новым письменным решением, зафиксированным в
этом каталоге.
